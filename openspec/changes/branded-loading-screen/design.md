# Design

## Context

See `proposal.md`. Today `apps/mobile/src/app/_layout.tsx` calls `SplashScreen.preventAutoHideAsync()`, loads Outfit, returns `null` until fonts are ready (or failed) and hides the native splash in an effect. `AppShell` composes `SessionProvider`, auth intent components and `RootStack`; `RootStack` shows a spinner for the first app status only (`useAppStatus`: session plus profile-complete) and keeps the previous status afterwards. `app.json` sets the splash plugin to blue `#208AEF` with `splash-icon.png`. Icons are the Expo template: `icon` is `assets/images/icon.png`, `ios.icon` is `./assets/expo.icon` (an Icon Composer asset, Expo blue with the Expo symbol, which iOS prefers over the PNG), Android's adaptive icon has background `#E6F4FE` with `android-icon-background.png`, `android-icon-foreground.png` and `android-icon-monochrome.png`, and the web favicon is `favicon.png`. `expo-splash-screen`, `expo-font`, `react-native-svg` and Outfit 800 are installed; `react-native-reanimated` is not a direct dependency (`react-native-worklets` 0.13 arrives only through `@expo/ui`). `expo-secure-store` is the only installed on-device store. Tokens: `colors.pink500` is `#E6005C`, `colors.pink100` is `#FFE3EE`, `colors.ink` is `#1A1218`, `fontFamily[800]` is `Outfit_800ExtraBold`.

The supplied package in `apps/mobile/assets/files/` (`FourthMark.tsx`, `AnimatedSplash.tsx`, `App.example.tsx`, `app.json.example`, `SPLASH-SETUP.md`, four PNGs) is the starting point. It is untested by its author. The design reference is `docs/Fourth loading animation.html` (a standalone preview of the same timeline, kept in `docs/`) and the canvas artboards Loading 1 to 4. The package folder is moved, not deleted (decision 14).

## Goals / Non-Goals

**Goals:** the supplied animation and its timing, wired into this app; first launch full, later launches short; correct final frame; tested logic.
**Non-Goals:** the rebrand of the Logo atom, Home and the app display name, slug, scheme and bundle identifier (issue #40), a shared in-app loader (#39), changing session or profile loading, Lottie or Rive.

## Decisions

1. **Code lives in `apps/mobile/src/splash/`, not `assets/`.** `assets/` holds images; `AGENTS.md` keeps non-route code outside `src/app`. Files: `timeline.ts` (pure), `fourth-mark.tsx`, `animated-splash.tsx`, `intro-seen.ts`, `launch-splash.tsx`. It is app-level and used once, so it stays out of `@padel/ui` until a second screen needs it.
2. **Fix the timeline: `TOTAL_MS = 2700`.** The supplied code uses 2500 but the wordmark interpolates over 2200 to 2700 ms, so at `progress = 1` it would be about 60% opaque and 5 px low. The HTML preview (the design source) ends the wordmark at 2700. Everything else keeps its times; the full intro minimum becomes about 2.7 s (about 3.0 s with the fade). A pure test pins the final frame (all balls at full radius, cell 28, dash offsets 0, wordmark opaque at offset 0), which also equals the app icon's arrangement.
3. **Extract the maths to `timeline.ts`.** `seg`, `easeOut`, `backOut`, and a `markFrame(progress)` that returns every radius, dash offset and the cell size are pure functions (still marked `'worklet'`), tested in jest without Reanimated. `FourthMark` reads them in `useAnimatedProps`.
4. **Use tokens, not literals.** Colours and the font come from `@padel/ui` (`colors.pink500`, `pink100`, `ink`, `fontFamily[800]`); the white variant stays as a prop, unused.
5. **`AnimatedSplash` gains `intro: 'full' | 'short'`.** `short` starts `progress` at 1 with no timer, so `introDone` is true at once and the screen fades as soon as `ready` flips. Reduced motion behaves like `short`. The supplied rules stay: it fades only when both `ready` and `introDone`, calls `onShown` once on first layout and `onFinish` once about 320 ms after the fade begins.
6. **Accessibility text is translated.** The supplied hard-coded `"Fourth, loading"` becomes an i18n key in the app namespace (English: "Fourth, loading").
7. **Where it mounts: `LaunchSplash` inside `AppShell`, after `RootStack`.** It needs `useAppStatus()`, which only works under `SessionProvider`, and fonts are already loaded because `RootLayout` renders nothing until then. `ready = appStatus !== 'loading'`. It renders nothing while it reads the seen flag (typed `LaunchState = 'checking' | 'playing' | 'finished'`), then `AnimatedSplash`. `RootStack`'s own first-status spinner stays as the fallback beneath it; the "first status only" rule is unchanged.
8. **The overlay owns hiding the native splash.** `AnimatedSplash.onShown` calls `SplashScreen.hideAsync()`, and the effect in `_layout.tsx` that hides it on fonts-ready is removed. If the overlay cannot mount the native splash would stay, so a font failure path still falls through: `LaunchSplash` hides the native splash itself if reading the flag throws.
9. **Seen flag in `expo-secure-store`.** It is the only installed store, needs no new native dependency, and a boolean under key `launch.introSeen` is harmless there. Trade-off: on iOS Keychain items can survive an uninstall, so a reinstall may skip the intro. *Alternatives:* `expo-file-system` (new direct dependency, wiped on uninstall) or AsyncStorage (new dependency). It sits behind `intro-seen.ts` (`readIntroSeen`, `markIntroSeen`) so the store can change. Non-native platforms (web) never read it and use the short version. Written when the intro reaches its end, never at the start, so an interrupted first launch plays again.
10. **`introFor({ seen, reducedMotion, native })`** is a pure function returning `'full' | 'short'`: unread or unreadable flag counts as seen (short).
11. **Native splash config.** The `expo-splash-screen` plugin entry changes: `backgroundColor` `#E6005C`, `image` the transparent `splash-blank.png` (copied to `assets/images/`; checked fully transparent). The package's `app.json.example` is not copied: it renames the app to "Fourth" and sets slug `fourth` (both left to #40); its icon settings are applied selectively in decision 12. Config-plugin changes apply only to native builds, not Expo Go.
12. **App icons from the package are adopted.** `icon.png` (1024), `adaptive-icon.png` (1024, foreground) and `favicon.png` (48) replace the content of `assets/images/icon.png`, `android-icon-foreground.png` and `favicon.png`, so those `app.json` paths stay as they are. Android: `adaptiveIcon.backgroundColor` becomes `#E6005C` and `backgroundImage` is removed (an image would cover the colour); `android-icon-background.png` is then unused. iOS: `ios.icon` points at `./assets/images/icon.png`, replacing the Expo-template Icon Composer asset (`assets/expo.icon`), because iOS would otherwise keep showing the Expo icon; the cost is that the layered "liquid glass" icon is not used until a designer makes a `.icon` for the mark. Unchanged on purpose: `name`, `slug`, `scheme`, `bundleIdentifier` and `android.adaptiveIcon.monochromeImage` (see Open Questions). Icon changes need a native build and do not show in Expo Go.
13. **Dependencies.** `npx expo install react-native-reanimated react-native-worklets` so versions match SDK 58. Before installing, read the SDK 58 docs for Reanimated (Babel is configured by `babel-preset-expo`, per the package's setup notes, which must be confirmed), Expo Go support, and the `expo-splash-screen` plugin options; do not rely on memory (see `apps/mobile/AGENTS.md`). Jest cannot use Reanimated's own mock here: it needs Worklets natives and Reanimated's Jest resolver matches any path containing "react-native-worklets", which pnpm puts in the folder names of many unrelated packages and so breaks native module resolution (checked with 4.7.1 and 0.13.0). The app uses a small deterministic stand-in (`src/__tests__/setup-reanimated.ts`) for the handful of APIs it calls: animations jump to their target, animated styles and props are evaluated at render, and reduced motion can be switched in a test.

14. **Reference package is moved, not deleted.** After the code is adopted, `apps/mobile/assets/files/` moves to `docs/design/fourth-splash/` (keeping `SPLASH-SETUP.md`, `app.json.example`, `App.example.tsx` and the PNGs as reference). `files.zip` is identical to that folder (checked) and is removed. Nothing is left under `apps/mobile/assets/files/` to be committed. `docs/Fourth loading animation.html` stays in `docs/`.

## Risks / Trade-offs

- [The new icon sits next to the old name: the label under the icon stays `padel-ralligo` and the Home screen says "Ralligo"] → accepted; the display name and wordmarks are issue #40.
- [Android themed icons show the Expo silhouette because the monochrome image is unchanged] → needs a monochrome version of the mark; see Open Questions.
- [Removing the Icon Composer asset loses the layered iOS 26 icon effect] → acceptable for now; a designer-made `.icon` can replace the PNG later.
- [Brand mismatch: the launch screen says "fourth." while the rest of the app says "Ralligo"] → accepted by the user for now; recorded as a follow-up.
- [Native splash and the overlay colour must match exactly, and Expo Go ignores the plugin] → `#E6005C` in both; the native check is a manual task on a real build. The local iOS build currently fails in `expo-modules-jsi` under Xcode 26.3, so verification waits for another build route (EAS dev build) or an Expo fix.
- [If the session or profile check never resolves, the overlay stays] → same outcome as the spinner today, so no new failure; a maximum wait is not added in this change.
- [Reanimated is a native dependency] → included in Expo Go; the dev build must be rebuilt after install.
- [Minimum first-launch time of about 3 s] → only once per device.
- [SecureStore flag can survive an iOS reinstall] → acceptable; the store is swappable behind `intro-seen.ts`.

## Open Questions

- **iOS icon:** confirm replacing the Icon Composer asset with the flat PNG (decision 12), or keep the old asset until a designer provides a `.icon` for the mark.
- **Android monochrome icon:** the package has no monochrome version. Leaving the Expo silhouette shows the wrong glyph in themed icons; removing it may fall back to a tinted version of the adaptive icon. Ask for a monochrome mark before the first store build.
